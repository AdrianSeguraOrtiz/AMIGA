# Installation and reproducibility

The repository contains the `amiga-exp` workflow, sharing AMIGA's project
version. Installing the PyPI package alone does not install this workflow or
the benchmark inputs. Version 0.2.0 is prepared as the next release.

## Installation

Use Python 3.11–3.13, Poetry and a Linux machine for the CPU-affinity execution
supervisors. Install the pinned dependencies from the committed lock file:

```bash
git clone https://github.com/AdrianSeguraOrtiz/AMIGA.git
cd AMIGA
POETRY_VIRTUALENVS_IN_PROJECT=true poetry install --with experiments
scripts/experiments/amiga-exp --version
scripts/experiments/amiga-exp --help
```

The wrapper uses the repository-local `.venv` when present. Set
`PYTHON=/path/to/python` to choose an interpreter explicitly. Run the commands
from the repository root.

## Required local inputs

GitHub contains source, tests, protocol specifications, predictor metadata and
topology assignments. It does not distribute processed datasets, fitted models,
predictions or experimental figures. Those files must be supplied separately;
a fresh clone alone cannot reproduce the benchmark without its inputs.

| Case | Input path | SHA-256 |
| --- | --- | --- |
| BIO-INSIGHT | `experiments/BIO-INSIGHT/data/data_104.csv` | `b95b2613481682e315250c7cf33433373f30db1100db352941cca43433c008f7` |
| MO-GENECI | `experiments/MO-GENECI/data/data_104.csv` | `c851b5c24dcd72e7f240cf36da284d29953325e1c1456619f054e6ab9d3f6cd6` |

Each case contains 104 fronts. The manifests in `contracts/` specify candidate
IDs, columns and feature sets. `groups/topology_groups.json` maps those fronts
to 87 whole-topology groups. To independently audit those assignments using the
source expression/reference collection recorded in that file:

```bash
poetry run python -m scripts.experiments.amiga_exp.grouped_validation.topology \
  --source-root /path/to/GENECI/input_data
```

The real application additionally requires the prepared TCGA-BRCA front, base
networks and fixed regulatory evidence described in [the application guide](real.md).

## Execution order

1. Supply the inputs and install the locked environment.
2. Run `benchmark selection`: [phases 1–3](sequential-selection.md).
3. Run `benchmark comparison`, then its `top5` and `top10` threshold analyses:
   [phase 4](outer-evaluation.md), [top-5%](top5-classification.md),
   [top-10%](top10-classification.md).
4. Generate `benchmark statistics` and `benchmark figures` from saved outputs.
5. Use `prepare` and `run` for the fixed learning curves and real-data deployment:
   [shared execution](supplementary.md).
6. Inspect `benchmark learning report`, `real report` and `costs report`.
   Optionally create the local index with `organize`.

Output destinations must be new. Contract builders refer to the dependency
paths shown in the command examples, so use a separate workspace to repeat the
complete sequence. Frozen runs preserve source/data hashes, model selections,
resource allocation, seeds and output identities. A changed implementation
requires a new execution contract; existing records are never rewritten to
claim they were generated by different code.

Workers use disjoint CPU sets and one BLAS thread per worker. Set `--jobs` and
`--threads` within the available affinity/cgroup quota. Runtime is machine
dependent. Resuming requires unchanged sources, environment, resources and
verified completed outputs.

## Verify the implementation without benchmark inputs

```bash
poetry run pytest --no-cov
```

Tests use temporary synthetic inputs and small native model fits. They cover
group isolation, labels, selection, final evaluation, saved-model prediction,
artifact integrity, score ties, Friedman ranks and Holm adjustment.
